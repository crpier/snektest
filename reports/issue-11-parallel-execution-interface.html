Issue 11 / second-pass interface review

Parallel execution with explicit resource ownership

Add one worker-count option, one named per-test mutex, and one honest run-owned fixture scope. Keep session fixtures worker-local. Make cross-process resource ownership and value transport explicit contracts.

01 / Verdict

Three controls, each earning its place

The run chooses process capacity. A test may declare one command-local mutex. A fixture may own one external resource for the invocation and distribute a descriptor snapshot. Global barriers, affinity, pool types, and shared mutable Python identity remain unsupported or private.

Pick this

Add -n COUNT / --workers COUNT, and add mutex: str | None = None to both @test and @test_hypothesis. Add @fixture(scope="run") for fixture-host-owned resources whose yielded descriptor can cross processes. Omit the worker option for in-process sequential execution.

Tests with the same non-empty, already-trimmed, case-sensitive mutex never overlap, while the scheduler may skip blocked cases to run unrelated work. The metadata governs this command's test invocations only; it is not cross-command locking, worker affinity, or cleanup of leaked descendants.

COUNT is a positive integer or auto. The latter uses the exact CPU/selected-case formula below. Issue 11 does not ship until issue 38 proves that full-plan replication stays within its memory budget at that count.

Default

Option omitted

Run sequentially in process, with no child hosts. Issue 28's deterministic precollection applies to both local and worker modes.

Process mode

--workers 1

One execution worker plus one persistent collector/fixture host. This reproduces worker-only behavior without concurrent tests.

Default in worker mode

--workers 4

Up to four persistent execution workers plus the host. Ordinary selected tests are eligible to overlap.

Per-test constraint

mutex="resource"

Tests naming the same command-global mutex run one at a time without forcing unrelated workers idle.

Do not call this full test isolation

Workers are persistent lanes. Tests in different workers do not share Python globals or event loops, but later tests in the same worker do. The filesystem, database, network ports, and other external resources remain shared by every worker. A mutex also cannot stop a thread or subprocess that a previous test leaked. A process-per-test feature would be a different contract.

Keep markers orthogonal

fast, medium, and slow describe resources. They neither imply nor override a mutex.

One run-owned value model

A run fixture yields a serialized descriptor snapshot. It never promises shared mutable Python identity, live clients, locks, files, or event-loop objects.

No scheduler menu

Other than one named mutex per test, callers should not rely on file, mutex-worker, or repeated-run affinity. Batching remains private.

The complete worker contract

A small interface works only if scheduling constraints and fixture ownership are precise. These rules should be documented and tested as part of issue 11.

Manifest ordering preserves the reporter model

Workers can finish out of order while the coordinator drains every IPC stream continuously and separately buffers the longest completed prefix. A slow early test can delay visible progress, but it must never stop reads from later workers and fill their pipes. Reporter callbacks remain serial and need no locks, but run_finished changes once to accept the normalized summary described below.

04 / Alternatives

Five shapes were tested again

The first idea is rarely the strongest. The options below optimize for different callers. Tether and snekql turn several hypothetical tradeoffs into concrete migration costs.

A / Recommended

Capacity, one mutex, run ownership

snektest --workers 4
@test(mutex="pi-runtime")
@fixture(scope="run")

Wins: maps directly to observed suites: capacity for the common case, one named mutex for conflicting or capacity-heavy tests, and one owner for a shared external server.

Cost: run fixtures add a real host and serialization contract; they must ship as a complete module, not a decorator-only shortcut.

B / Too little

Worker count only

snektest --workers 4

Wins: smallest implementation and familiar xdist behavior.

Loses: snekql has six tests sharing one table plus a session daemon that cannot be started per worker. Tether also benefits from limiting concurrent Pi subprocess tests. Splitting commands is not a fixture model.

C / Double opt-in

Positive test eligibility

@test(parallel=True)
def test_a() -> None: ...

Wins: safest default for an unreviewed suite.

Loses: Tether would annotate 1,522 decorated functions and snekql 651 even though process isolation already makes nearly all of them safe. The explicit worker option is the suite-level opt-in.

D / Coarse fallback

Atomic test files

# scheduler promise:
# one file stays on one worker

Wins: snekql's six conflicting tests already share one file; module globals and session reuse become simpler.

Loses: file layout silently becomes scheduling policy, large files cap utilization, and conflicts can still cross files. A named mutex states the actual constraint.

E / Control panel

Published scheduler policy

ProcessExecution(
    workers=4,
    dispatch="file",
    affinity="fixture",
    progress="completion",
)

Wins: exposes every implementation choice.

Loses: callers learn pool and batching internals with no second implementation to justify them. The observed needs are constraints, not scheduler selection.

Rejected backend

Same-loop async concurrency

It speeds only suspended async work and supplies no process isolation. More importantly, it conflicts with current internals:

  • Output capture replaces process-global sys.stdout and sys.stderr.
  • The fixture registry has one shared function stack.
  • Leaked-task snapshots would see tasks owned by neighboring tests.

This can be designed later under its own name after those modules become task-safe.

06 / Downstream fit

Two suites force the missing decisions

Tether and snekql together contribute 2,173 decorated test functions. Their current fixture and resource patterns reject both extremes: annotating every safe test is needless churn, while making every test parallel with no mutex or run owner breaks concrete integration tests.

Tether

1,540 expanded cases; almost all isolated

In-memory SQLite, unique temporary directories, process-local logging, and one-test-per-worker execution make the default suite parallel-safe.

One development-server test has a port reservation gap, but runner exclusivity cannot close a host-level TOCTOU race; Tether should preserve bound sockets through child startup or retry. Eight real Pi process tests benefit from mutex="pi-runtime".

snekql

651 tests; one truly shared server

Sixty-three tests consume a session MariaDB fixture backed by the fixed .snektest/mariadb-data directory. Per-worker setup would start competing daemons on the same data.

The fixture already yields a frozen connection descriptor rather than the subprocess. Moving it to scope="run" fixes in-command ownership. Six bulk-insert tests sharing one table need one mutex; the retained data directory still needs a command-unique path or a lease that survives the host and detects stale owners.

08 / Validation

Evidence, not just preference

The recommendation was checked against the current code, open hardening issues, Python 3.14 process behavior, serialization probes, nine runner models, and 2,173 decorated tests in Tether and snekql.

Live results fail the process test

Pickling a real failing TestResult produced TypeError: cannot pickle 'traceback' object. This is a hard blocker, not a theoretical concern.

TracebackException is not a drop-in wire value

A Python 3.14 probe also failed while pickling TracebackException because frame summaries retained code objects. Snektest needs its own immutable frame snapshot.

Callables and parameters must stay local

TestCase stores a function and arbitrary Param.value objects. Making parallel mode require picklable test data would be a new and poor test-author contract.

Manifest equality has a hard limit

Workers can collect the same case name with different random, time-based, or PID-based values. Compare structural metadata and keep values local; do not claim that a matching manifest proves value equality.

Fork inheritance cannot be the design

Python 3.14 defaults differ by platform. Start every private host with an explicit spawn-style context instead of inheriting loop, thread, tracer, or imported-module state.

Process workers fit async hygiene

Each worker can retain one serial event loop, so task snapshots, async timeouts, session fixtures, and process-global capture keep their current local assumptions.

The real run descriptor passes the transport probe

snekql's frozen TemporaryMariaDBServer descriptor round-trips through stdlib pickle with its host, port, paths, and methods intact. The owning subprocess remains inside the fixture host.

The public scope interface is already inconsistent

annotations.Scope accepts literals while the exported enum is a different type and public Scope.SESSION is misinterpreted. Issue 31 must fix that before adding RUN.

Deterministic collection is a prerequisite

Functions are currently alphabetized by getmembers, file walks are unsorted, and duplicate case names can overwrite one another. Issues 28 and 32 must define the canonical manifest before ordinals and mutex scheduling depend on it.

The reporter stays coordinator-owned, not unchanged

Callbacks remain serial, but issue 36's normalized run result must represent process provenance and run-fixture lifecycle failures before the worker protocol is frozen.

Coverage is not yet confirmed

Coverage.py documents separate startup requirements for multiprocessing or subprocesses plus clean worker shutdown. parallel = true solves only data-file collisions.

Long-lived workers need honest wording

pytest-xdist, Go, Cargo, Node, Vitest, ExUnit, and nextest all show that process/thread/task topology changes what "isolation" and fixture lifetime mean. The report states snektest's narrower promise.

Contract tests required before release

  • After deterministic precollection, omitted workers preserve representative local pass, fail, fixture, timeout, debugger, and output behavior.
  • --workers 1 starts one execution worker plus one host, runs tests in a different PID, and uses the same result schema.
  • Same-mutex tests never overlap; the scheduler skips blocked ordinals and runs different-mutex or unguarded work when capacity exists.
  • Both test decorators and every parameterized case preserve identical scheduling metadata.
  • Overlapping filters preserve filter order and produce distinct ordinals for every repeated occurrence.
  • The default empty plan fails before workers start; a future explicit allow-empty mode produces a host-only zero-test summary.
  • An unused run fixture performs zero setup; different top-level setups serialize; duplicate loads share one shielded operation.
  • First setup/publication pauses at a fleet safepoint; workers stage one bounded descriptor and expose it only after the coordinator's COMMIT.
  • A decode NACK makes every worker discard staged data and caches one publication failure; process loss or watchdog expiry aborts the run.
  • Run-to-run dependencies tear down in reverse order; cycles and invalid cross-scope dependencies fail clearly.
  • Unpicklable parameter values stay local; an unpicklable or oversized run value fails as an attributed publication error.
  • One cancelled waiter does not cancel shared work; the transaction watchdog covers setup, pickle, decode, and acknowledgement.
  • New fixture loads during teardown or after shutdown starts fail without reopening the graph or fleet.
  • Session setup is once per process incarnation, and replacement can increase setup count beyond configured workers.
  • Initial host and workers bootstrap one at a time; timeout, exit, collection failure, or structural mismatch aborts before test execution.
  • Crashes in body, function teardown, result send, idle state, session teardown, and fixture host follow distinct documented paths.
  • Replacement imports begin only after all surviving active tests finish.
  • Controlled infrastructure aborts call run_finished with active uncommitted cases aborted and every unstarted case not run.
  • A fatal run-teardown stall reports the current and all remaining host fixtures as teardown lost.
  • Large out-of-order results cannot deadlock because all worker connections remain drained.
  • --pdb, breakpoint(), stdin, -s, and the rejected -s --json-output combination follow the contract.
  • Ctrl-C reaps workers and the fixture host, attempts bounded teardown, and does not deadlock a full result pipe.
  • Explicit spawn-style startup passes on Linux, macOS, and Windows in CI.
  • Coverage data from workers combines to the same measured source set as local execution.
09 / Implementation

Preconditions behind the seam

The public interface is small. The implementation is not. The result model should become process-neutral before any worker code is trusted.

First migration: value-based diagnostics

FailedResult, ErrorResult, and TeardownFailure currently expose live exception and traceback objects. Parallel execution cannot preserve those identities. Use one immutable diagnostic model in both local and worker modes rather than a mode-dependent union. 

@dataclass(frozen=True)
class TracebackFrame:
    filename: str
    lineno: int
    function: str
    source: str | None

@dataclass(frozen=True)
class ExceptionReport:
    qualified_type_name: str
    message: str
    frames: tuple[TracebackFrame, ...]
    notes: tuple[str, ...]
    assertion: AssertionReport | None = None
    cause: ExceptionReport | None = None
    context: ExceptionReport | None = None
    exceptions: tuple[ExceptionReport, ...] = ()

Local debugging still gets live state

The local adapter may retain a private exception and traceback until --pdb finishes. Those objects should not enter TestResult, reporting, JSON, or the worker protocol.

This is a clean pre-1.0 change, but it affects repository tests and any caller importing models directly. Release notes must name it.

Change the final reporter callback once

class RunReporter(Protocol):
    def test_finished(self, test_result: TestResult) -> None: ...
    def run_finished(self, summary: TestRunSummary) -> None: ...

TestRunSummary becomes the normalized run value returned by the programmatic API and consumed by console, JSON, JUnit, and custom reporters. It contains one manifest-ordered case entry per selected ordinal, including aborted and not_run. This is a pre-1.0 programmatic compatibility break and belongs in the migration notes.

Recommended internal flow

  1. Start the canonical collector/fixture host under the command-timeout watchdog. Finish deterministic collection, apply the empty-plan policy, assign distinct ordinals to repeated selections, reject colliding parameter-case identities, and register top-level run fixtures.
  2. Build a manifest from normalized file identity, function and case names, markers, and mutex; build a run-fixture catalogue from module and qualified name.
  3. Resolve auto exactly as the lesser of available process CPUs and selected case count. Start non-daemon execution workers one at a time under the same watchdog.
  4. Each worker independently collects and matches both structures before the next worker starts. Keep local callables and arbitrary parameter values; do not claim that equal structure proves equal values. Any bootstrap failure aborts without retry.
  5. Send only ordinals for tests. The coordinator owns mutex permits, scans past blocked cases, and marks an assignment active before sending it.
  6. On a first run-fixture request, stop dispatch and drain non-waiting active tests. The transaction watchdog covers host setup, serialization, staged worker decode, ACK/NACK, and COMMIT/DISCARD. A process failure aborts rather than exposing a partial value.
  7. Execute one test at a time per worker through existing timeout, function-fixture, memory, output, and leaked-task logic.
  8. Drain every framed worker and host connection continuously. A complete result frame commits its ordinal; ordering buffers never control IPC reads.
  9. After an active-test crash, stop new dispatch, let surviving active tests finish, then import and validate a replacement before resuming. Never import replacement modules alongside tests.
  10. After dispatch ends, freeze the dependency graph. Tear down surviving worker sessions, then host-owned run fixtures, in reverse dependency order and under bounded cleanup. If the host must die, mark every unattempted run teardown lost.
  11. Normalize provenance, diagnostics, lifecycle output, infrastructure failures, and every unstarted case into one run result; flush committed test callbacks in manifest order and finish once after controlled aborts.
Prefer

Explicit spawn-style startup

Private collector and execution hosts start clean on every supported operating system. They never depend on the platform's default process start method. Exact entry points stay private.

Require

Dedicated protocol

Do not multiplex control messages with test stdout/stderr. Use framed messages over dedicated connections and explicit EOF/crash handling.

Require

Non-daemon children

Tests and run fixtures may launch subprocesses, including snekql's MariaDB server. Neither execution workers nor the fixture host may be daemonic.

Repeated collection is a measured cost, not a free invariant

Full local collection avoids serializing test functions and parameter values, but imports selected modules in the canonical host and every worker. Capture bootstrap output, present the canonical copy only, and surface secondary output only for mismatch diagnostics. Issue 38 must measure the multiplied memory before issue 11 ships; the runtime must not silently alter auto's documented formula with an undisclosed cap.

Run scope is a host protocol, not shared memory

The host keeps the original yielded object for teardown. Workers receive independent pickle round-trips. A file handle, client, lock, closure, event-loop object, or mutable registry is the wrong value; return an immutable path, URL, port, credentials, or frozen configuration descriptor and build worker-local clients in session or function fixtures. A frozen descriptor can still mutate one shared external resource, so all conflicting tests must name the same mutex and cross-command ownership remains the fixture author's job.

10 / Risks

What can still sink it

None of these risks argues for a larger caller interface. They argue for sequencing the implementation and refusing weak fallbacks.

Blocker
Live result objects
Tracebacks and arbitrary exceptions do not cross the protocol. Migrate diagnostics under local execution first and verify presenter parity.
High
Assertion detail loss
Snapshot conversion must preserve useful dict/list diffs and safely bound hostile repr() calls. A string-only exception message is not enough.
High
Parameter value drift
Random, PID-based, time-based, or externally mutable values can differ while structural manifests still match. State this limitation; only structural mismatch is detectable without imposing serialization on parameters.
High
Crash and interrupt deadlocks
Worker death while writing a result can corrupt or stall naive queues. Exercise EOF, full buffers, signals, forced kill, and child reaping with real processes.
High
Fixture ownership
Documentation currently says session fixtures run once per run. Every guide must define worker-incarnation sessions, host-owned run fixtures, descriptor copies, dependency limits, and teardown order together.
High
Run-value misuse
Pickle success and a frozen descriptor do not make the referenced external resource immutable. Validate bounded transport, use trusted local channels, and require complete mutex coverage for conflicting external mutations.
High
Host setup stalls
Serial host setup protects process-global capture but one hung fixture blocks every later request. Watch the complete publication transaction, distinguish cooperative fixture failure from process termination, and document that --no-timeout removes the bound.
High
Partial publication
A local pickle round-trip does not prove clean-worker importability. Workers must stage bounded payloads, ACK or NACK, and expose a value only after COMMIT. Process loss during the transaction aborts the run.
High
Fixture-host loss
A host crash can orphan an external daemon and loses run teardown. Abort without recreating the fixture and report exit 2. A later command needs a unique resource or a lease that survives the host and validates stale owners.
High
Single-host teardown loss
A sync or cancellation-resistant teardown can force host termination. Report the current fixture and every remaining fixture as teardown lost; do not promise an attempt after their owning process is gone.
High
Import side effects
Every child repeats selected imports. Bootstrap the host and workers serially, never import replacements beside active tests, and abort on timeout or mismatch. Sequential startup limits overlap but cannot make arbitrary import side effects idempotent.
High
Mutex boundary
A mutex is exact and command-local, not affinity or an OS lock. Avoid claims about other commands, leaked descendants, or resources used by tests that omit the same name.
High
Coverage startup
The root sitecustomize.py is not a general installed-user guarantee. Verify startup, clean shutdown, unique data files, and combine behavior for the chosen worker host.
Medium
Oversubscription
Each worker may start Hypothesis threads, asyncio.to_thread, BLAS threads, or subprocesses, and each retains a full plan. Issue 38 must prove the exact auto formula stays within the release budget.
Medium
Head-of-line reporting
Canonical manifest order can hide later completions behind one slow test. Accept this in v1 to preserve the reporter interface; revisit only with user evidence.
Medium
Worker state leakage
Persistent workers still share globals between assigned tests. Say so. Do not imply that adding workers repairs every order-dependent suite.
